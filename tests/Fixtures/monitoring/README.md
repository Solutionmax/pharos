# Controlled monitoring acceptance fixtures

These scripts exercise native transports against disposable infrastructure and never run against the deployed status page. They are deliberately outside PHPUnit's default test discovery. Run them with an isolated migrated SQLite database (set `DB_DATABASE`); create a fixture account only in that database for browser tests.

TLS/S3 server: use a disposable Alpine container on a private Docker address. Install python3/openssl, generate a two-day TLS certificate with that address in its subjectAltName, then copy `storage-server.py` into the container. It expects `/tmp/fixture.pem`, `/tmp/fixture.key` and listens on 9443. It serves `/up` and `/redirect` as HTTP probe fixtures, and a private `/fixturebackup/` S3 bucket with SigV4-authenticated PUT/GET/DELETE. The fixture access key/password are fixed test-only strings in its source. Run PHP with `-d curl.cainfo=/path/to/fixture.pem`: the production service continues requiring verification. Running without that CA must fail TLS.

`php tests/Fixtures/monitoring/tls-probe.php https://<container-ip>:9443` proves same-request certificate expiry, two-day degradation, exact keyword failure, and a metadata redirect that is not followed. `remote-roundtrip.php` receives a private JSON file containing the same `BackupDestination` fields as the admin flow; it proves real filesystem writes, full SQLite/files archive writes, reads and SHA256 equality. Example S3 configuration keys: `endpoint`, `allow_private: true`, `region: us-east-1`, `bucket: fixturebackup`. Example credentials: `key: pharosfixture`, `secret: Fixture-s3-secret-123`. For SFTP use disposable openssh in the same container, a fixture-only account, private `root`, and verify `fingerprint` from `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`. Never reuse fixture credentials outside testing.

DNS server: in that disposable container run dnsmasq with `no-resolv`, `no-hosts`, `host-record=fixture.example.test,192.0.2.55,2001:db8::55`, `cname=alias.fixture.example.test,fixture.example.test`, `mx-host=fixture.example.test,mail.fixture.example.test,10`, `txt-record=fixture.example.test,hello world`. Execute `dns-probe.php` in a disposable PHP container with `--dns=<fixture-server-ip>` and the project mounted read-only. This exercises PHP's actual DNS A/AAAA/CNAME/MX/TXT lookups and the monitor result.

Browser passkey proof uses `agent-browser` and Chrome CDP WebAuthn.enable/addVirtualAuthenticator (ctap2_1, internal, hasResidentKey, hasUserVerification, isUserVerified, automaticPresenceSimulation all true), kept connected throughout the ceremony. The fixture administrator logs in by password on `http://localhost:<port>`, registers a named passkey on Your profile, logs out, uses Sign in with a passkey, and removes that key using the current password. Check stored counters and last_used_at, and keep screenshots outside the application/package. The localhost exception is valid WebAuthn; it does not prove passkey usability on an HTTP LAN IP.
